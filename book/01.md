## 2. Install TipTap

### What is tiptap?

Tiptap is a javascript library for building apps like notion or google docs

With Tiptap you can start in minutes, choose from tons of amazing extensions and still have that powerful ProseMirror API accessible when you really need it.

To install tiptap in our `nextjs` application, we can run this command

```
> npm i @tiptap/extension-link @tiptap/extension-image @tiptap/extension-placeholder @tiptap/ex tension-underline @tiptap/extension-text-style @tiptap/extension-color @tiptap/extension-task-item @tiptap/extension-task-list tiptap-markdown @tiptap/extension-highlight @tiptap/react @tiptap/pm @tiptap/starter-kit
```

Lets try to understand what have we installed

Extensions:
- @tiptap/extension-link 
- @tiptap/extension-image 
- @tiptap/extension-placeholder

- @tiptap/pm @tiptap/starter-kit

Core Library:
- @tiptap/react: core library

## 3. Install chadcn

Chadcn is the best React UI library I have used. Two reason why it rocks:
1. Template based
2. Code Organization
2. First Class Accessibility (via Radix UI)


Lets expand on those two key points

1. Template based

One of the main problems with most ui libray is that they are `npm` based. Meaning the components live somewhere in the cloud. This has two big implications:
- You have no control over the actual source of the component (since you are using it via npm)
- Since you have no control over the actual source, you are at the mercy of the authors. Suppose in the future the author decides to change the name of the package from `foo` to `bar`, this means if you want to use the new library, you'd have to refactor your app..

What if there was a better way. What if there was a tool that solved both of these issues: chadcn

chadcn comes with the cli. you can tell the `cli` to generate a component (ex: button, alert) and the cli will literally write that component in your source.


2. Code Organization

You will see what I mean shortly :)


3. First Class Accessibility

The third and the biggest reason why chadcn rocks.

Accessibility is a big deal with web apps. An accessible website means you are thinking of people with disabilities as well. The problem with web that it does not support accessibility natively (due to historical reasons). So its up to the developers to implement accessibility. But implementing accessibility is very hard. It requires a deep expertise and the room of error is very high.

Alright lets fially install `chadcn`

```sh
> npx shadn-ui@latest init

- Would you like to use TypeScript (recommended)   > yes
- Which style would you like to use?               > Default
- Which color would you like to use as base color? > Slate
- Where is your global CSS file?                   > app/globals.css
- Would you like to use CSS variables for colors?  > yes
- Where is your tailwind config.js located?        > tailwind.config.js
- Configure the import alias for components:       > @/components # (1)
- Configure the import alias for utils:            > @/lib/utils
- Are you using React Server Components?           > yes
- Write configuration to components.json. Proceed? > Yes

```


This will create a folder named `components`. This is where we will define all of our basic + custom components. It will also create another file named `lib/utils.ts`

This is how the app structure looks like:

```
.
├── app
│   ├── layout.tsx
│   └── page.tsx
├── components
│   ├── ui
│   │   ├── alert-dialog.tsx
│   │   ├── button.tsx
│   │   ├── dropdown-menu.tsx
│   │   └── ...
│   ├── main-nav.tsx
│   ├── page-header.tsx
│   └── ...
├── lib
│   └── utils.ts
├── styles
│   └── globals.css
├── next.config.js
├── package.json
├── postcss.config.js
├── tailwind.config.js
└── tsconfig.json
```
